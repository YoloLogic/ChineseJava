## ⚠ 两个上游本地化 bug 与本地补丁（不是我们的语言补丁，须与关键字补丁分开看）

**现象**：中文 Windows 上 `configure` 直接失败：
```
configure: error: Target CPU mismatch. We are building for x86_64 but CL is for "版"; expected "x64".
configure: WARNING: You are using microsoft 用于 x64 的 … 版 which is older than 19.28.0.0.
```

**根因（都在 `make/autoconf/toolchain.m4`）**：

| # | 位置 | 原实现 | 中文下的后果 |
|---|---|---|---|
| 1 | `TOOLCHAIN_MISC_CHECKS`（原 921–922 行） | `sed "s/^.* \(.*\)$/\1/p"` 取横幅**最后一个空格分隔的词** | 英文 `… for x64` → `x64` ✔；中文 `用于 x64 的 … 编译器 19.44.35228 版` → **`版`** ✘ |
| 2 | `TOOLCHAIN_EXTRACT_COMPILER_VERSION`（原 345–346 行） | `sed 's/^.*ersion.\([1-9][0-9.]*\) .*$/\1/'` 依赖英文单词 **ersion** | 中文横幅无此词 ⇒ 整行被当版本号 ⇒ 误报"比 19.28 老" |

**本地补丁**：两处都改成"先找已知 CPU 标识 / 先取第一个点分版本号"，**取不到再退回原逻辑**（英文行为完全不变）。
**注意**：m4 用 `@<:@` / `@:>@` 表示方括号，写字面 `[` 会导致 `m4: ERROR: end of file in string`（我踩过一次，已修）。
**归口**：这是**上游 bug 的本地绕过**，不是 ChineseJava 的语言特性；将来上游修好后应删除，并另存为 `patches\` 下的独立补丁以便区分。

## 构建命令与日志

```powershell
pwsh -File tools\构建.ps1 -Check        # 环境检查
pwsh -File tools\构建.ps1 -Configure    # 只配置
pwsh -File tools\构建.ps1               # 配置 + make images + 中文关键字冒烟
```
日志目录：`构建日志\`（`msys2-安装.log`、`构建-<时间戳>.log`）；构建产物：`jdk\build\cnjava\images\jdk`。
