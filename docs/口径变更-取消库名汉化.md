# 口径变更：取消 java 库汉化（2026-11）

> **一句话**：本派生**只汉化关键字（L2）与诊断（L1），不汉化任何库名**。
> 原 L3「中文标准库名字层」及其支撑（含 HotSpot 的一处安全放宽）**整体退役**。

## 一、为什么

| 原因 | 说明 |
|---|---|
| 成本/收益 | 库名层要做 7,443 个顶层公开类型 × 成员别名，判据面巨大；而"能写 `列表<字符串>`"对大多数用户不是刚需。 |
| 维护负担 | 名字表是**第二份真相**，要跟随上游每次 API 变化重测（且已出现 4 条记错所属类型的错账）。 |
| 安全代价 | 为让汉语平行库占用 `java.工具.函数`，必须在 HotSpot 放宽 `java.` 命名空间检查。这是**有意的安全让步**；库名层取消后它就只剩代价。 |
| 一致性 | 关键字是"语言"的一部分，库名是"标准库"的一部分。只做前者，边界干净、可解释。 |

## 五、删除了怎么恢复

退役前已做**仓库外**备份（本仓库工程根未被 git 跟踪，删了 git 里找不回）：

```
E:\ChineseJava-L3-退役备份-<时间戳>\
  备份说明.txt
  tools\标准库名表.tsv
  tools\生成标准库名表.ps1
  tools\接线标准库名层.ps1
  docs\L3设计.md
  docs\中文标准库名表.md
  jdk\src\...\comp\ZhLibNames.java
  jdk-当前改动版\   ← 退役前 4 个被改的上游文件的完整副本
```

恢复步骤（**先想清楚**：恢复名字层必须同时恢复 `docs\硬边界台账.md` 第二节那处安全放宽，
否则汉语平行库占不了 `java.工具.*`）：

1. 把 `tools\*`、`docs\*`、`ZhLibNames.java` 按原相对路径拷回；
2. 从 `jdk-当前改动版\` 恢复 4 个上游文件；
3. 恢复 `tests\跑批6判据.ps1`；
4. 跑 `pwsh tools\生成标准库名表.ps1` 再生成两处产物；
5. 跑 `verify.ps1` 确认全绿。

## 六、这次变更对判据的影响

* `verify.ps1`：环境检查移除库名表与 `ZhLibNames.java`；生成器 `-Check` 只剩关键字与诊断两个；
  移除"派生层接线"检查。判据套件改为**自动发现** `tests\跑批*判据.ps1`（删掉的批6 自然不再跑）。
* `跑批4判据.ps1`：K4-8/K4-9 原本测库名表，改为测**关键字表**↔产物一致与守卫可失败；
  K4-10 台账关键词从「窄放行/7,445」改为「Object 五钩子 + main」。
* `跑批1 / 2b / 5`：**完全不动**（它们不依赖库名层）。
