# ChineseJava 硬边界台账

> **口径来源**：用户裁定「**按 Chinese++ 的口径办**」（2026-10-10）。
> Chinese++ 的做法是：能汉化的全部汉化（**复制层**），汉化不了的列为**硬边界**——
> **如实记账、保持英文、不硬来**（它有 14 个这样的硬边界：12 个函数式宏 + 2 个 MSVC 内部类型别名）；
> 英文名由**派生层**补回，所以英文生态不断。
>
> **2026-11 口径变更**：本派生**只汉化关键字（L2）与诊断（L1），不做任何库名汉化**。
> 因此下面凡标「复制层 / 派生层 / 汉语副本 / 汉语糖」的条目，现状态一律是 **⬜ 不做**；
> 与之配套的 `java.` 命名空间窄放行**已回退**（见第二节）。详见 [口径变更-取消库名汉化.md](口径变更-取消库名汉化.md)。
>
> 本台账逐条写清「哪一处不能或不该汉化、为什么、我们怎么处理」，每一条尽量配一条**能失败的判据**。

## 一、语言层硬边界（VM 写死，改不了也不该改）

### 1. `java.lang.Object` 的 5 个钩子：`toString` / `equals` / `hashCode` / `clone` / `finalize`

* **为什么不能改**：`java.lang.Object` 是 HotSpot **写死的根类**（VM 按名字找 `java/lang/Object`），**不能复制**；
  而 JVM 里"覆盖"是按「**名字 + 参数**」配对、占父类同一个 vtable 槽位的 ⇒ 叫 `转字符串` 的方法**不构成覆盖**。
* **实测证据**（同一份代码，只差方法名）：

  | 副本里的方法名 | `System.out.println(新建 点(3))` |
  |---|---|
  | `转字符串`（汉语） | `点@251a69d7` ✗ |
  | `toString`（英文原名） | `点(3)` ✔ |

* **处理**：**保留这 5 个英文名当钩子**。原计划的"在汉语副本里另给汉语糖
  （`转字符串()`、`相等(对象)`、`哈希码()`、`克隆()`、`终结()`，内部转发到钩子）"**已取消**——
  库名层整体退役，没有"汉语副本"可用。**状态：⬜ 不做**（不是"未实现"，是"决定不做"）。
* **判据**：`tests\跑批4判据.ps1` K4-2 保证原库英文侧零影响；`对象@哈希` 与 `toString` 的对照实验见上文（仍可复现）。

### 2. 不可复制的 VM 核心类型

`Object`、`Class`、`String`、`Thread`、`Throwable`、`System`、`ClassLoader`、`Module`、`MethodHandle` 根 …
（HotSpot 用 `vmSymbols` 按名字找它们，改名后 VM 起不来）

* **处理（2026-11 口径变更后）**：这些类型**保持英文、不提供任何汉语名**。
  原先设想的"汉语平行库里的包装类（如 `java.语言.字符串` 包装 `java.lang.String`）"已随库名层整体取消。⇒ **不做**。
* **判据**：原库类型照旧可用；任何汉语名指向它们都必须"找不到符号"（`tests\跑批4判据.ps1` K4-3/K4-4 的命名空间不变式）。

### 3. 程序入口 `main`

HotSpot 的启动器按名字找 `main` ⇒ 叫 `主函数` 的方法**不是入口**（这与库名层无关，是 VM 写死的）。
处理：入口方法名**仍写 `main`**；关键字、类型、局部名都可以用中文：

```java
公开 类型 甲类 {
    公开 静态 空型 main(String[] 参数) {   // ← 只有 main 这 4 个字母是英文
        整数 计数 = 0;
        System.out.println("你好");
    }
}
```

## 二、命名空间：**原来的窄放行已撤销**（2026-11 口径变更）

> **口径变更**：用户决定 **取消 java 库汉化，只保留关键字 + 诊断汉化**。
> 原第二节那处「`java.` 后紧跟非 ASCII 段即放行」的窄放行，**唯一目的是让汉语平行库能占用 `java.工具.函数`**。
> 平行库取消后它只剩余副作用，因此**整处补丁已回退**（`git checkout` 恢复上游原貌）。

* **现状（= 上游原样）**：`java.` 开头的包/模块，只有 boot / platform 类加载器能定义；
  普通类加载器一律 `Prohibited package name`（运行期）、`程序包已存在于另一个模块中`（编译期）。
  拦路处仍是 3 处（`NOTICE.txt` 登记），但**一处都没有放宽**：
  1. `src/hotspot/share/classfile/modules.cpp`（定义模块的包）
  2. `src/hotspot/share/oops/instanceKlass.cpp`（加载类，快路径 + 慢路径）
  3. `src/java.base/share/classes/java/lang/ClassLoader.java`（Java 层 `preDefineClass`）
* **不变式**：`java.*` **不可伪造**（与上游一致）。
* **判据**：`tests\跑批4判据.ps1` 的 K4-7 用同一份字节请求 `java.lang.aaaaaaaaaaaaa` ⇒ **必须被拒**；
  用汉语名请求 `java.工具.*` ⇒ **必须同样被拒**（放行已不存在）。

## 四、刻意不译的（上游口径，与 Chinese++ 一致）

| 东西 | 为什么 | 我们的处理 |
|---|---|---|
| 诊断前缀 `error:` / `warning:` / `note:` | 编辑器问题面板与 CI 靠它抓日志 | 前缀默认英文，**正文**中文；可用 `CHINESEJAVA_PREFIX=zh` 切 |
| class 文件名、JNI 名、序列化名、JPMS 名 | 工具链与生态靠它 | **不动** |
| `--help` 输出、警告开关名（`-Xlint:…`） | 构建系统靠它 | 未汉化（第一版不做） |
| `_` 等下划线开头的实现扩展 | 翻了反而干扰 | 不译 |
| 英文既有资源包的键名 | `CreateSymbols` 从英文包生成 `Errors/Notes` 类 | 只**追加**我方新键，既有键一行不动 |

**新增元判据（审计建议 3，已进 `verify.ps1` 第 3.5 节）**：每条判据的输出里
**不许出现被吞的异常**（`InvalidOperation` / `MethodInvocationException` / `NullReferenceException` / `不能对值为 Null`），
**不许出现空判词**（`[ok]` 后面什么都没有）。判据「绿得没有证据」与「假绿」同等对待。

**7,443 的口径（可直接复现）**：扫 `jdk\src` 下所有 `java.*` 模块的 `share\classes\**\*.java`，
按行首 `public` 类型声明计数，正则：
`(?m)^public\s+(?:(?:final|abstract|sealed|non-sealed|static|strictfp)\s+)*(?:class|interface|enum|record|@interface)\s+\w+`
（前缀修饰符计入；嵌套类因有缩进不计）⇒ 22 个模块合计 **7,443**。
审计员独立计数 7,428（差 15，0.2%），文档旧值 7,445（差 2，0.03%）——三者落在 0.3% 内，
根因是正则边界（如 `public @interface`、修饰符顺序）与快照差异；**该数字只用于分母，不影响任何判据结论**。
